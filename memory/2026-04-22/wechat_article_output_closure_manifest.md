# 公众号文章输出目录化闭环清单

## 背景

此前公众号文章相关产物会直接散落在 `output/` 根目录，Markdown、最终 HTML、预览页和素材目录之间也存在路径约定不一致的问题。随着文章迭代次数变多，这种“根目录直出 + 旧路径兼容混写”的方式开始同时带来三个问题：

- 当天文章和历史文章资源容易互相覆盖，难以回溯某次发布对应的完整产物集。
- `wechat_article.md`、预览 HTML 和最终发布 HTML 的资源引用口径不一致，容易出现本地能打开、迁移后失效的路径。
- `output/` 既承担真实产物目录，又承担兼容入口，职责混杂，不利于后续自动化生成与草稿同步。

## 本次收敛

- 新增 [output/wechat_article_generation_constraint.md](../../output/wechat_article_generation_constraint.md)，将公众号文章的目录结构、引用规则、生成步骤和发布前检查正式收口为长期约束。
- 文章产物改为必须落到独立目录 `output/sonic-lens_article_YYYYMMDD/`，不再把正文和素材直接散落在 `output/` 根目录。
- `output/` 根目录职责收敛为“兼容入口层”：
  - 保留约束文件。
  - 保留指向最新文章目录的符号链接，如 `wechat_article.md`、`wechat_article.html`、`wechat_preview*.html`、`wechat_assets`。
- Markdown、正文 HTML、读者版 HTML、预览 HTML 的资源引用规则统一：
  - `wechat_article.md` 引用公共静态资源时使用 `../static/...`。
  - 文章目录内部资源统一引用 `./wechat_assets/...` 或 `wechat_assets/...`。
  - 禁止继续写死 `output/wechat_assets/...` 这类旧路径。
- 发布流程新增显式门槛：只有用户确认最终读者版后，才允许同步公众号草稿箱。

## 长期约束

- 公众号文章的事实源是“当天文章目录中的完整产物集”，不是 `output/` 根目录中的散落文件。
- `output/` 根目录只作为稳定兼容入口存在，不再承担真实文章资源的长期存储职责。
- 任何新增的预览页、读者版或素材目录，都应优先放在当天文章目录内部，再通过符号链接暴露兼容入口。
- 文章正文应以读者最终看到的内容为准，内部制作说明、生成过程备注不得泄漏到读者版 HTML。

## 对 GEMINI 的影响

- 这次变化属于“生成物目录化 + 兼容入口化”的流程约束，而非新的业务实体或数据库规则。
- 因此 `GEMINI.md` 只保留一条总入口链接，并建议把这类规则抽象为独立母规则：真实产物进独立目录，根目录只保留稳定入口与兼容层。
