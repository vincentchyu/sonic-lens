# Bridge 专辑库三端闭环与性能收敛记忆清单

## 日期

- 2026-03-20

## 背景

- `soniclens-bridge` 的资料库此前虽然已经切到“本地 SQLite 轻量索引 + 增量同步 + 详情懒加载”，但专辑页仍存在三类问题：
  - 专辑卡片会被长标题和长作者撑出不一致的形状。
  - iPhone 直接复用桌面详情布局，头图区在窄屏下出现文字纵向挤压。
  - 专辑列表和详情页在高密度滚动时使用了过重的玻璃材质、hover 和动画，导致三端 CPU / Energy 明显偏高。
- 本轮迭代只收口专辑相关闭环，不改后端协议，继续依赖 `/api/albums`、`/api/albums/:id` 和本地索引排序/搜索能力。

## 本次沉淀的事实标准

### 1. 专辑列表卡片是固定模块，不允许再被文案撑形

- 专辑网格必须采用“先算列数，再反推出统一卡片宽度”的方式；同一屏同一行的卡片宽高必须一致。
- 专辑卡片的封面区和文字区属于同一个固定模块：
  - 卡片总宽固定
  - 卡片总高固定
  - 封面保持固定比例
  - 标题最多 2 行
  - 作者最多 1 行
  - 超长文本统一截断
- 卡片间距属于视觉规则的一部分，必须显式给出跨端 spacing，不能让内边距或 overlay 造成视觉重叠。
- 专辑卡片的元信息（如发行时间、播放数）只能占用卡片内部固定元信息区，不能参与撑宽或撑高。

### 2. 专辑排序语义与曲目排序语义分离

- `LibrarySort.releaseDate` 是专辑列表专用排序项，不应自动扩散到曲目列表。
- `LibrarySortMenu` 必须按业务场景传入独立 options：
  - 专辑列表使用 `LibrarySort.albumOptions`
  - 曲目列表使用 `LibrarySort.trackOptions`
- 本地索引层的专辑发行时间排序事实标准为：
  - 非空 `release_date` 优先
  - 然后按 `release_date DESC`
  - 再按专辑名和 `id` 稳定排序

### 3. 专辑详情必须走“共享内容 + 平台容器”结构

- `AlbumDetailViewModel` 继续作为三端共享数据加载层。
- 专辑详情入口统一由 `albumDetailDestination(albumID:)` 提供，避免列表、首页等入口各自硬编码不同详情页实现。
- 详情页结构固定为两层：
  - 共享内容层：`AlbumDetailContentView`
  - 平台容器层：桌面/平板使用常规容器，iPhone 使用紧凑容器
- 可复用的 section 骨架（如 `DetailSectionCard`）允许被歌曲详情等页面复用，但不要反向把窄屏布局绑回桌面容器。

### 4. iPhone 详情不能直接套桌面头图

- iPhone 专辑详情必须使用“上图下内容”的纵向 Hero 结构。
- iPad / macOS 可以保留更宽松的横向 Hero，但应继续复用同一套详情数据模型与 section。
- 手机端曲目行只保留必要信息密度：
  - 左侧曲序
  - 中间标题与必要副信息
  - 右侧时长
  - 长文本不允许撑高或破坏滚动密度

### 5. 多碟专辑必须按 `disc_number` 分组展示

- 专辑详情的曲目区不能再把多碟曲目混成一个平铺列表。
- 当存在多个碟号时，必须按 `disc_number` 分组并显示清晰的碟头（例如“光盘 1”、“光盘 2”）。
- 组内排序优先使用 `trackNumber`，再用稳定键兜底。
- 未标记碟号的曲目应落到显式的兜底分组，而不是悄悄并进第一碟。

### 6. Bridge 高密度列表/详情性能约束

- 专辑列表和专辑详情都属于高密度滚动面，默认不允许在每个 cell / row 上叠加昂贵效果：
  - 重玻璃材质
  - 大阴影
  - hover scale
  - 随数据量变化触发的整页动画
- 高密度区域优先使用静态背景、细描边和轻量状态切换；若要加动效，必须先验证滚动 CPU / Energy 不明显回升。
- 共享 section 容器若用于长列表，应优先支持 `isSimplified` 这类轻量视觉分支，避免把展示页的重视觉直接下沉到所有详情页。

## 已完成的页面闭环

- 专辑网格页 `AlbumGridView.swift`
- 专辑详情页 `AlbumDetailView.swift`
- 专辑排序菜单与场景隔离 `AppLayoutView.swift` / `PadAppLayoutView.swift` / `PhoneAppLayoutView.swift`
- 本地索引专辑排序 `LibraryIndexStore.swift`
- 首页等专辑详情跳转入口已切到共享 `albumDetailDestination(albumID:)`

## 后续迭代约束

- 若继续改专辑列表密度，先改共享卡片度量和截断规则，不要回到“文字决定卡片尺寸”的布局。
- 若继续改专辑详情样式，优先调整共享 section 和平台容器边界，不要把 iPhone 再次拉回桌面布局。
- 若后续引入真实专辑封面或更多元信息，必须在固定卡片尺寸内消化，不得破坏统一网格。
- 若后续滚动性能再次恶化，先检查每行/每卡片的材质、阴影、hover 和动画，再排查数据层。
